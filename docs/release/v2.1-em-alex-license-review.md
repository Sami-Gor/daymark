## 1. Executive conclusion

The exact voice file used by Daymark is the `em_alex.bin` file in
`onnx-community/Kokoro-82M-v1.0-ONNX`. Its SHA-256 matches the value pinned by
Daymark's fetch script. Both the base Kokoro-82M repository and the ONNX
conversion repository declare **Apache License 2.0** for the repository/model
weights; the base README describes the weights as Apache-licensed and
explicitly welcomes production and commercial deployment.

That is direct evidence for copyright licensing of this asset, not an
assumption based on the runtime licence. It permits redistribution inside the
Android application and commercial distribution if Apache-2.0 conditions are
met.

It **does not** establish who the original speaker was, what recording or
dataset produced this speaker embedding, or whether any separate
speaker-likeness/consent right exists. Those questions remain unresolved and
are not answered by the Apache grant from the model publisher.

## 3. Provenance chain

1. **hexgrad/Kokoro-82M** publishes the Kokoro-82M model and its built-in
   Spanish voice style `voices/em_alex.pt`.
2. **onnx-community/Kokoro-82M-v1.0-ONNX** publishes an ONNX conversion of the
   same model and converts the voice style to `voices/em_alex.bin`.
3. Daymark downloads that exact `.bin` from the ONNX repository, verifies the
   pinned SHA-256, copies it into the Android voice assets, and loads it
   through the pinned `pguso/kokoro` runtime.
4. Daymark does not modify the voice bytes. The only known transformation is
   the upstream PyTorch-to-ONNX Community `.pt` → `.bin` conversion.
