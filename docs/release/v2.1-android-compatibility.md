# V2.1 Android compatibility and device-validation matrix

**Status:** static and automated validation complete; runtime device validation
is pending. This document does not claim that any phone or OEM is verified.

**Scope:** the Daymark V2.1 POC branch (`poc/multilingual-android-tts`), the
weather app under `artifacts/weather-app`, and its `daymark-voice` Android
module. It does not describe the shipped V2.0.0 artifact or production signing.

The minimum was **not** lowered. It is the existing V2.0.0 application baseline
(Android 10), while Capacitor itself supports API 24. The 32-bit and x86
native ABIs are excluded because the Kokoro JNI library and the selected
sherpa-onnx build are arm64-only. A device that cannot install an arm64 build
must not be described as compatible.

The base APK carries the Kokoro model and voices, but not the Parakeet model.
A local `:app:assembleDebug` run at this commit produced an
`app-debug.apk` with zero `parakeet/` entries; `:app:bundleDebug` produced a
`parakeet` asset-pack module containing the four model files. Installing the
debug APK is therefore adequate for TTS and UI checks but **not** for offline
voice input: the speech plugin reports `model-missing` and refuses to start
recording. Use an app bundle (see §4) for STT validation.

### Local emulator availability

The development machine has existing AVD definitions for API 24, 26, 29 and
30 and matching system images under the Android command-line SDK. API 29/30
are the only ones inside the supported range. This pass did **not** install an
APK/AAB or run the app; there is no instrumentation suite in the branch. The
AVDs are therefore available for a future approved runtime pass, not evidence
of current runtime compatibility. An AVD pass must use the bundled/asset-pack
install path for voice input; the standalone debug APK cannot exercise it.

## 3. API behaviour review

### AudioRecord / microphone

- The recorder is created, started and checked on a bounded worker, never on
  the UI thread.
- Reads use `READ_NON_BLOCKING` with a bounded poll loop, so cancellation can
  be observed and the 30-second cap remains enforceable.
- `RECORD_AUDIO` is checked immediately before recorder construction, closing
  the permission-revocation race between the session-level check and
  `AudioRecord`.
- A security exception is mapped to a permission outcome; construction,
  start-state and read failures are mapped to an audio-capture outcome.
- The device is released on every path, including cancellation during recorder
  creation and cancellation during decode.
- Before any of that, the plugin checks for `parakeet/encoder.int8.onnx`,
  `decoder.int8.onnx`, `joiner.int8.onnx` and `tokens.txt` in the installed
  app's assets. They are supplied by the install-time pack. When they are
  absent, `isAvailable` reports `model-missing` and `start` rejects before the
  recorder is constructed.

### AudioTrack / narration

- One worker owns synthesis and playback; a monotonic generation invalidates
  old work when a new utterance starts or the user stops.
- A stale generation cannot create a new track, publish a completion, emit a
  second terminal error, or overwrite the newer state.
- Every playback path releases `AudioTrack` in `finally`, and clears the
  engine's track reference only if it still owns it.
- Synthesis and playback failures are recoverable: the engine returns to
  `READY` and the user can retry. Initialization failures remain terminal until
  the plugin is recreated.
- `AudioFocusRequest` is used on API 26+ with the legacy overload below that.
  Focus is abandoned on stop, pause, failure and destroy. A focus loss stops
  playback rather than resuming it automatically.
- The WebView/native bridge has no browser or Android system-TTS fallback.
- A generation check stops playback promptly, but it cannot interrupt a native
  synthesis call already in progress. This affects French/Spanish, which
  synthesize the whole utterance in one `nativeSynth` call; see
  `v2.1-speech-performance.md` §5 and the device risks listed there.

### Location

- Android 12+ approximate location is the intended and only declared level.
- The shared resolver applies the 0.025-degree latitude floor and the
  latitude-aware longitude step before a weather request.
- No permission is requested on launch; the default London forecast works
  without location permission.
- Denial, permanent denial, timeout, unavailable, invalid fixes and stale
  background results have separate recovery paths.
- GeoNames lookup is local and receives no coordinates.

### WebView

- The native gate reads the installed WebView package and blocks major versions
  below 90. Unknown or unreadable versions fail visibly.
- The fallback is a native screen with localized English/French/Spanish copy,
  not a blank WebView.
- `MainActivity` checks that the packaged `public/index.html` entry point
  exists before starting the Capacitor bridge; a missing bundle gets a native
  reinstall/update screen.
- A bridge/listener failure is surfaced as an unavailable narration state; it
  does not fall through to browser speech or system TTS.
- Post-bridge local chunk, JavaScript and CSS failures report through the
  `DaymarkRecovery` bridge where available; the native `DaymarkWebViewClient`
  detects local asset errors when the bridge is not available. Only the
  Bridge's resolved local origin is eligible, so Open-Meteo/API failures stay
  in the ordinary weather error path.
- Native recovery offers one reload attempt, suppresses duplicate/parallel
  failures and then shows update/reinstall guidance instead of looping.
- The gate is a feature-compatibility floor, not a security certification.

## 4. OEM/device validation matrix

No OEM compatibility claim is made. The following matrix is the future plan.

| Device class | Status | Risks to exercise |
|---|---|---|
| Google Pixel (reference Android) | **Not tested** | Audio focus, `AudioTrack` buffer behaviour, background pause/resume, WebView update path |
| Samsung Galaxy | **Not tested** | Audio focus policy, microphone routing, WebView implementation, aggressive background limits |
| Nothing Phone | **Not tested** | AudioTrack underrun/initialisation, model-loading memory pressure, microphone handoff |
| Xiaomi/Redmi | **Not tested** | Background restrictions, permission-prompt suppression, WebView variant |
| OnePlus/Oppo/Realme | **Not tested** | Audio focus, WebView variant, memory pressure |
| Other arm64 Android 10+ devices | **Not tested** | At minimum: install, cold start, microphone, playback, locale switch, airplane mode |

Required future device checks. These are procedures, not results. Run speech
input (STT) and narration (TTS) as separate passes so a narration pass cannot
hide a missing recogniser.

### Precondition: install the Parakeet asset pack

The Parakeet model is an install-time asset pack, not part of the base APK. A
standalone `:app:assembleDebug` APK therefore cannot validate offline voice
input. The supported path is:

1. Stage the model with
   `android/kokoro-poc/scripts/fetch-parakeet-assets.sh`. The script verifies
   the pinned archive and file digests.
2. Build an app bundle, for example `:app:bundleDebug` (POC application ID) or
   `:app:bundleRelease`.
3. Install the bundle's generated APK set (`bundletool build-apks`, then
   `bundletool install-apks`), or install through Play internal testing. Do not
   install the standalone `app-debug.apk` for STT.
4. Before enabling airplane mode, confirm the app reports voice input as
   available. If it reports `model-missing`, the pack is not installed; if it
   reports `model-preparing`, wait for the first-run materialisation.

A bundle inspection should show a `parakeet` module with
`<dist:type="asset-pack"/>` and `<dist:install-time/>`. The generated APK set
contains an `asset-slices/parakeet-master.apk` with the four model files under
`assets/parakeet/`.

### Voice input (STT) checks

1. Airplane mode with Wi-Fi off: recognize a spoken request, confirm the
   transcript and the on-device Parakeet path are used, and confirm no network
   speech path is attempted.
2. Permission denied once, denied permanently, and revoked while a session is
   active.
3. Background during capture; return to foreground and cancel/retry.
4. First-run model materialisation, then a low-storage or failed-integrity
   start. Confirm `model-missing`/`model-corrupt` are reported distinctly and
   the recorder is not left open.
5. No audio or transcript is logged or persisted.

### Narration (TTS) checks

1. Airplane mode with Wi-Fi off: English, French and Spanish narration using
   the bundled Kokoro engine; no system/browser TTS.
2. Measure time-to-first-audio separately per language, from the tap to the
   first audible sample. Record English and French/Spanish separately; §5 of
   `v2.1-speech-performance.md` explains why their synthesis paths differ.
3. Rapid stop/start and locale switch without overlapping audio. Record both
   the API's return to idle and whether native synthesis actually stopped.
4. Peak memory and long-utterance latency for 500-word narration.
5. Background during playback; return to foreground.

### Shared checks

1. WebView older than 90 and a normal updated WebView.
2. Install, cold start and locale switch on at least one physical arm64 device.

Until those run, the supported status is **implemented and statically tested;
device validation pending**.
