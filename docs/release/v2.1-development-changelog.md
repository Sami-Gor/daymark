```bash

pnpm --filter @workspace/weather-app run build
pnpm exec cap sync android

pnpm --filter @workspace/weather-app run typecheck
pnpm --filter @workspace/weather-app run test

cd artifacts/weather-app/android
./gradlew --no-daemon :daymark-voice:testDebugUnitTest :app:testDebugUnitTest
```

The web build and Capacitor sync are required in a fresh checkout before the
unit suite runs: `network-boundary.test.ts` reads generated
`android/app/src/main/assets/public` and `capacitor.config.json` files. A first
unit run without those generated assets failed 2 of 363 tests; after the normal
build/sync prerequisite it passed. This is a checkout prerequisite, not a V2.1
implementation failure.

## Preserved V2.1 scope

The implementation plan prepared before Phase 0 remains authoritative. Scope
areas and phase order are preserved:

| Area | Scope | Status at baseline |
|---|---|---|
| A | Compound voice-intent parsing for rain, temperature, wind, and other conditions | Partial — core multi-intent resolver exists; needs broader vocabulary and coverage |
| B | Complete multi-part weather answers, including all requested details and missing-data handling | Partial — combined response exists; needs completeness/de-duplication contract |
| C | French and Spanish offline narration through the UI | Not implemented — English Kokoro only |
| D | Canonical 500-word integrated speech-accuracy benchmark, manifest, and scorer | Partial / not ready — 207-word standalone evidence only |
| E | Long utterances, decoding latency, slow/timeout behaviour, recovery | Partial — 30 s cap, endpointing, phase watchdogs |
| F | Voice lifecycle, repeated sessions, OEM microphone behaviour, API 29+ | Partial — strong JVM coverage; physical/OEM coverage open |
| G | WebView and unavailable-native-service fallback UX | Partial — old-WebView screen and explicit voice errors exist |
| H | Location permission denial/revocation and supported-version coverage | Source implemented; physical coverage partial |
| I | Packet-level privacy/security evidence, dependency/native review | Partial — source guards; packet capture open |

## Implementation phases

1. **Phase 0 — baseline and changelog** (this entry; complete).
2. **Phase 1 — A + B:** intent completeness and multi-part answer quality.
3. **Phase 2 — C:** French/Spanish on-device narration, asset integrity, UI.
4. **Phase 3 — D, then E:** canonical 500-word benchmark, then long-utterance
   decoding and recovery.
5. **Phase 4 — F + G + H:** voice lifecycle/OEM compatibility, fallback UX, and
   location physical coverage.
6. **Phase 5 — I:** privacy/security evidence, packet-capture windows, dependency
   and native-library review, release-readiness reconciliation.

No phase may merge into production or `main`, publish the GitHub draft, alter
the V2.0.0 tag, upload to Google Play, or modify production signing material.
